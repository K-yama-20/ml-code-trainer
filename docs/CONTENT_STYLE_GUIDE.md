# Drill教材の設計・記述ガイド

Pythonの基礎を理解している機械学習初学者が、問題を開いてすぐコードを書き始められることを目指す。2026-11の具体入力方式を現在の基準とする。旧版の教材・提出は書き換えない。

## 最初に示すもの

タイトル、短い課題、具体的な入力コード、明確な解答欄、答え合わせを中心にする。学習のポイント、テストの列挙、よくある間違い、詳細な解説は初期表示へ持ち込まない。結果のない出力パネルも開かない。

タイトルは対象と動作を示す。「各行の平均を計算する」のように書く。問題文は「xの各行の平均を求め、1次元のNumPy配列resultに代入してください」のように、処理と受け取り先を短く伝える。shape等の制約は必要なものだけ添える。

悪い例：

> NumPyの集約演算APIを適切に活用し、指定された軸方向に対する統計的処理を実装してください。

良い例：

> 配列xの各行の平均を計算し、1次元のNumPy配列resultに代入してください。

```python
import numpy as np

x = np.array([
    [1., 4., 5.],
    [2., 10., -4.]
])

result = x.mean(axis=)
```

「適切に」「同様に」「指定の処理」「境界条件を確認」だけで指示を終えない。「公開テストを参照」「solveを実装」だけで入力や目的を説明したことにしない。専門用語を先に並べない。

## 具体的な入力と期待結果

- 提供コードは学習者の解答と分離し、読み取り専用にする。引数の意味を想像する作業を要求しない。
- 小さく手計算できる入力を優先する。行・列や軸の区別が学習目標なら、複数行で示す。
- 長い規則的な配列はarangeとreshapeでもよい。巨大な実データは代表例・shape・列を示す。
- dtype、index、欠損値、Tensorの転置・非連続性、requires_gradも入力の一部。値だけが同じ別の入力へ置換しない。
- 期待結果は表示用入力に対応させる。平均の例は約[3.333333, 2.666667]。丸めた表示値を厳密一致の採点基準にしない。
- 空入力、列の保持、dtype一致など、合否に関係する条件を説明する。特定のshapeがすべての採点入力で固定であるかのように書かない。
- 出力予測の正解は初期画面に表示しない。予測は表示コード1つについて答える形式とし、異なる非公開入力を予測させない。

## 解答欄と段階

| 段階・形式 | 提供するもの | 学習者が書くもの |
|---|---|---|
| Guided | 入力と処理の骨格 | 何も入力されていない1か所。例：axisの数値 |
| Partial | 入力とresult =、または実際の修正対象 | 必要な式や複数行の処理 |
| Independent | 入力と開始コメント | 結果の代入を含む処理全体 |
| 出力予測 | 入力と観察するコード | 数値、shape、辞書、配列の値を専用欄へ |
| バグ修正 | 入力と不具合のある解答コード | 指示された処理の修正 |
| メソッド実装 | クラスの枠組みと使用例 | forward等の処理とreturn |

入力を抽象化することを難化と呼ばない。NP05-01の行平均、NP05-03の列合計、NP05-05の画像ごと・チャネルごとの平均のように、応用する対象・まとめる軸にも変化を付ける。

提供コードを解答欄へコピーさせない。printは観察用で、採点対象はresultまたは明示した関数の戻り値。例外として関数・メソッドの実装が目的ならreturnを要求する。

## 関数・クラスを残す基準

NumPy、Pandas、scikit-learn、基本Tensor操作では原則script形式を使う。採点の都合だけでdef solve(x)を見せない。

引数・既定値・*args・**kwargs自体、任意入力の関数設計、Dataset実装、nn.Module、forward、関数としての学習ループ設計が目標なら、その構造を維持する。名前を具体的にし、入力と使用例を併記する。今回の関数形式はPY02の4問。nn.Moduleの3問は外側の採点用solveだけを取り除き、クラスとメソッドを維持する。既存Dataset問題はTensorDataset等の利用であり、自作Datasetクラスの実装問題ではない。

## ヒント

1. 具体的な入力の何に注目するか。例：「2行あるので平均も2つ残ります」。
2. 使用するAPIと操作の意味。例：「meanのaxis=1は各行の中の列をまとめます」。
3. 実際の書き方。例：「空欄は1です。x.mean(axis=1)と書けます」。

旧3段階データは保持するが、現行UIでは代表的な第2ヒントを1つ表示する。第3ヒントに解答が含まれてもよいが、閲覧を記録し、独力の認定と区別する。入力名や結果の受け取り方は表示コードと一致させる。Guidedの第3ヒントは空欄へ入れる部分を具体的に示す。他の移行問題はscriptの実例を提示するが、第1・第2ヒントの教育的品質まで自動変換で保証したことにしない。

## 解説と誤答

解説は表示入力で短く計算を追い、なぜその処理になるか説明する。NP05-01なら(1+4+7)/3=4と(2+6+10)/3=6を示す。

「よくある間違い」は誤操作→具体入力→異なる結果を書く。NP05-01でaxis=0では[1.5,5,8.5]となり、求める2つの行平均とは違う、という形にする。概念の別問題の注意をそのまま配らない。

誤答時は実値・期待値を比べられるようにし、見直す場所と理由を伝える。検知していない原因を「あなたは間違えた」と断定しない。入力変更、文法エラー、実行エラーを計算結果の不一致と混同しない。非公開入力の値・出力・エラー詳細を表示しない。

## 問題定義と採点

- 原定義：content/catalog.py。既存Phase 1の著者定義：content/drill_phase1.py。
- 具体入力アダプター：content/concrete.py。今回の詳細改稿15問：content/concrete_lessons.py。
- コンパイル：scripts/compile_content.py。生成JSONだけを直接編集しない。
- workspace：表示用コード、課題、使用例。execution：信頼する問題版に紐づく実行契約。starter_codeとsolutionは解答部分だけを持つ。
- script採点は各ケースの提供入力を先に生成し、学習者の処理を実行してresultを検証する。クライアントから入力定義やexecutionを受け取らない。
- 表示例の数値をコピーしただけでは通らないよう、値・shapeを変えたケースを作る。変更後の全模範解答、代表誤答、異なる実装による別解を検証する。
- 特定APIが目標である問題だけ静的条件を併用する。新script版では呼び出しを検証し、単なる同名属性の参照とは区別する。ASTは完全なプログラムの意味の証明ではない。
- 同じ出力になるAPI練習では直接の定数代入も検査する。ただし任意コードによる巧妙な偽装を完全に検出できるとは主張しない。
- 公開と非公開の入力は正式採点でも別Sandboxへ渡す。期待値と比較はSandboxの外に保持する。

## バージョンとレビュー

入力UI・解答コード・観察対象・採点契約を変えたら版を上げる。旧版・seed42/99をcontent/versions/へ保存し、古いitem・Attempt・Draftは当時の版のまま読めるようにする。今回の移行は180問のworkspace仕様、詳細改稿は15問。他165問の文章をすべて新規執筆・初学者検証したわけではない。全件の判断と未完了事項はDRILL_PROBLEM_CLASSIFICATION.mdを参照する。

初学者に「すること・使う入力・書く場所」を言い換えてもらい、最初に編集するまでの迷いとヒント後の行動を観察する。自動採点と画面テストだけで理解しやすさを合格にしない。

入力変数の再初期化・再代入は解答と区別する。一方、問題文で禁止されていないin-place演算まで一律に落とさない。配列の同じ値とshapeを作る別解と、入力の差し替えを区別して検証する。

## 2026-11 統一Monaco仕様（この節を表示方式の最新基準とする）

提供コードと解答コードを別の表示領域へ分けない。内部では別々に管理し、単一Monacoの連続したPythonコードとして表示する。provided_codeは固定。原本の単一の `___` または骨格の単一の `pass` は編集位置を表し、初期画面では空欄になる。穴埋めと関数・メソッドの骨格の外側は固定し、自由記述・バグ修正では解答ブロックを編集できる。新しい問題のために個別のUIを追加しない。

初期の左側はタイトル、短い課題、閉じたヒント、閉じた模範解答の順にする。「求める結果」「入力・読み取り専用」「ここに解答を書く」のカードや案内で重複させない。型・shape・index等の重要な制約は課題本文に短く含める。

ヒントは既存3段階を無条件に削除せず、代表的な第2ヒントを1つ表示する。閲覧記録は既存APIのレベル2を使用し、習熟度の利用有無を維持する。模範解答は正解前でも閲覧でき、コードだけを折りたたみ内に表示する。閲覧によって下書き・提出を変更しない。

確定済みの18問対応教材は原本の単一ヒントを使う。NP01の原本は `content/arrays.json` とし、全ステージで固定の入力コードと `result =` を提供する。ステージを理由に空欄や関数定義へ変更しない。別ケースでは、問題文で固定した入力条件を維持する。NP01第2問は2行3列、第17問は0次元、第18問はshape `(0, 4)` を保つ。第8問のdtype名は `str(x.dtype)` でもよい。第17・18問のように入力を変えても期待値が変わらない属性問題は、値の比較と属性使用の確認を組み合わせる。

zipの良い例：「配列keysをキーに、valuesを値にした辞書をresultに代入してください。長さが異なるときは、短い側に合わせます。」不適切な例：「zipで辞書を返す。処理の結果をresultに代入してください。」

NP02の確定原本は `content/indexing.json` とする。次元が変わる整数指定とスライスを区別し、列の順番と重複、境界値、該当なしの場合のshapeを採点に含める。NaNだけを除く問題で、無限大まで除いて正解になるケース構成にしない。

判定直下の `result` は、表示入力に対応する最初の公開ケースの実値だけを表示する。dtypeの表示とdtypeの採点条件を区別する。値が0・False・空配列・Noneでも表示し、実行エラーや古い履歴で実値がない場合は値を補わない。編集中の結果には、既存の「変更前の結果」の表示を適用する。

NP03の確定原本は `content/reshaping.json` とする。変形前後の要素順、軸を追加する位置、削除する軸を別ケースで確認する。長さ1の軸がすべて消える0次元配列と、バッチ数0の空配列も採点する。shapeは配列の値とともに保持し、0次元配列を通常の数値へ置き換えて判定しない。第15・17問のバッチ数など、問題文の正のサイズ条件も維持する。viewは正答であり、コピーの作成を追加条件にしない。

NP04の確定原本は `content/axis_permutation.json` とする。バッチ・時刻・高さ・幅・チャネルの意味を入力順と対応させ、shapeだけが一致するreshapeも誤答として検出する。軸の長さが異なる入力と、各要素を区別できる値を採点ケースに含める。画素ごとの行では、行内のチャネル値と画素の読み取り順の両方を比較する。

NP05の確定原本は `content/reductions.json` とする。行・列の集約を非正方形の入力で区別し、スカラーと配列、keepdimsで残す長さ1の軸も採点する。argmaxは最初の最大値の位置、標準偏差はddof=0を検証する。画像の別入力には高さと幅が異なる例、バッチ数・チャネル数が1の例を含める。明示されたkeepdims=True・ddof=0は対象APIの引数として検査し、変数や辞書で渡す別解も許容する。第17問は入力の値・shape・dtypeを保護し、第18問は行数0を保って列数を変える。

NP06の確定原本は `content/broadcasting.json` とする。全問で入力を保護し、行・列・チャネル・バッチに対応する値を座標ごとに検証する。行数と列数、チャネル数と空間軸の長さが異なる別入力を含める。軸追加の方法を限定せず、None・reshape・expand_dimsも受け入れる。第17問だけbroadcast_toの呼び出しを指定し、読み取り専用viewを正答とする。第18問は点数・中心数・特徴数を変え、全ペアの軸順と二乗距離を検証する。

NP07の確定原本は `content/combining.json` とする。別入力で結合する軸や並べる順序の誤りを見つける。0次元入力、バッチ1個、両方が空の配列を含める。第18問ではタプル型を変換前に確認し、特徴量とラベルを個別に比較する。

NP08の確定原本は `content/conditional.json` とする。境界に等しい入力を含め、指定されたdtypeと値を比較する。無限大と範囲外の有限値を区別し、条件付き除算では分母0に対応する分子が0の場合と非ゼロの場合を両方含める。
