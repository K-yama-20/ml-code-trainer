# Drill統一エディタ・UI実装報告

## 変更したもの

Drillの左をタイトル・課題・ヒント・模範解答に整理し、右は単一Monacoと最小限の結果・操作にした。提供コード用のpre領域と別エディタは廃止。初期表示の編集案内、出力仕様カード、ヒントの段階表示、閲覧・提出後の長い記録説明を取り除いた。正解時は判定と件数を表示し、動作確認とprint出力は折りたたむ。

変更箇所：AnswerWorkspace.tsx（統一エディタ）、DrillView.tsx（問題・アコーディオン・結果・操作）、Drill.tsx（代表ヒントの取得）、Drill.css（レイアウト）。採点ハーネス・Run/Submitの区別・認証・テーマの保存復元は変更していない。

## 編集保護

1つのMonacoモデルに提供コード、解答部分、必要なら使用例を連結する。行番号・フォント・インデントは同一モデルのものを使う。保存・実行へ渡すのは解答部分だけ。提供入力は従来どおり問題定義からケースごとに与え、表示コードを採点用入力として信用しない。

Guidedの___は編集可能な区間。単一passの関数・クラスではその本体を編集区間とし、周囲を固定する。その他は解答領域を編集可能にし、既存の関数・クラス宣言を保護する。保存済みの別形式のコードは捨てず、広い解答領域で復元する。

すべての変更を検証し、固定prefix/suffixや宣言の変更は保存せず、イベント処理完了後のmicrotaskで有効な状態へ戻す。Backspace、Delete、範囲をまたぐ貼り付けも同じ検証を通る。Ctrl+Aは編集区間を選択する。Undo/Redoは公開ITextModelの入口に接続し、検証済みのスナップショットだけを履歴へ入れる。不正操作をUndo履歴に残さず、通常の文字入力は500ms単位、複数行や貼り付けは操作単位で扱う。最大200スナップショットを保持する。

これはフロントエンドの編集保護であり、採点のセキュリティ境界には使わない。正式な入力・期待値はサーバー側の問題定義と隔離実行で扱う。

## ヒント・模範解答

両方とも独立したdetailsで、初期は閉じる。ヒントは既存第2ヒントを代表として1つ表示する。初めて開く際に既存のreveal APIでlevel 2を記録する。旧3段階データとAPIは削除せず、既存の閲覧済みレベルは下げない。習熟度の「ヒント利用あり」の判定は維持。

模範解答はいつでも開け、既存reveal APIでsolution_viewedを記録する。閉じるとコードは非表示。閲覧だけでは提出・コードの上書きをしない。

## 問題定義と180問

zip（PY01-03）を@3へ更新し、旧@2をv3-seed42/99のスナップショットへ保存した。タイトルと文章を簡潔にし、表示例をkeys=['a','b']、values=[2,3]にした。長さが異なる採点ケースも残す。NP05-05も軸の並び順を課題本文へ明記して@3へ更新した。その他178問の教材本文・採点条件は変更していない。

全180問は共通のProblem/DrillViewを使う。160問のコード形式は統一Monaco、20問の予測は既存の値入力欄を使う。全コード問題で初期コードの保存・表示の往復をUnitテストし、模範解答の採点は既存Backendテストで検証する。新規教材はprovided_code、starter_code、___またはpassによる編集区間、ヒント、模範解答、ケースを定義すればよい。問題IDによる個別UI分岐はない。
