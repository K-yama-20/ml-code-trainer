# Drillの具体入力・解答エディタ改善 実装報告

実施日：2026-11-03〜04。対象はDrillと問題データ・実行インターフェース。認証方式・学習履歴のテーブル・習熟度の認定基準は変更していない。

## 1. 変更した画面と構造

- `DrillView.tsx`：課題、求める結果、入力コード、解答を中心に表示。空の結果パネルは初期状態で閉じる。解説・間違い例・動作確認は解答後。予測の模範解答にも採点用関数を見せない。
- `AnswerWorkspace.tsx`：提供コードを読み取り専用にし、Guidedは空欄、Partial・Independentは解答コードだけを編集する。コードは視覚的に一続きで読める。保存済みの異なるコードは消さずにMonacoへ戻す。
- `Drill.tsx`：未入力のまま実行環境を起動しない。Run/Submit、コード変更後の結果の区別、保存・競合・キャンセルは維持。
- `answer.ts`、`python.ts`、`python.worker.js`：問題形式に対応する表示・予測値の互換アダプター・実行契約。
- `content/concrete.py`：原問題のASTと実際の公開fixtureからworkspaceを生成。外側の採点用関数だけを除き、クラス内のreturnを保つ。転置Tensorの生成式・dtype・requires_gradを保持する。
- `content/runner.py`、`worker.py`、`grading.py`：信頼する問題版から入力を準備しresultを検証。特定APIが目標の既存条件は呼び出しを確認する。公開・非公開は別Sandboxに分ける。

## 3. 変更例と3段階

従来は入力がコード面に見えず、`def solve(x): return x.mean(axis=___)`を編集していた。

現在のNP05-01：

```python
import numpy as np

x = np.array([
    [1., 4., 5.],
    [2., 10., -4.]
])

result = x.mean(axis=___)
```

提供部分は編集できず、空欄へ1を入力する。期待結果は約[3.333333,2.666667]と説明する。後の解説は、この2行の値で計算を追う。

| 段階 | 代表問題 | 書く範囲と応用 |
|---|---|---|
| Guided | NP05-01：行平均 | axisの空欄。行の数だけ平均が残る |
| Partial | NP05-03：列合計 | resultの右側。列を残す軸とsumを選ぶ |
| Independent | NP05-05：画像・チャネル平均 | 代入を含む処理全体。高さ・幅の2軸をまとめる |

入力を段階的に抽象化するのではなく、具体入力を保って処理の範囲を広げた。PT05-03はforwardの実装そのものが目的なので、クラス・メソッド・末尾の使用例を残した。SK02-04では実際にtrainとtestを混ぜてしまう初期処理を提示し、fitの対象を直せるようにした。

## 4. 採点とデータの扱い

Runは公開入力だけで動作確認する。Submitは従来どおり履歴保存を伴い、Sandbox利用時は公開・非公開の両方を正式採点する。ブラウザーのみの判定は暫定のままで、Independentの正式認定へ格上げしない。

scriptでは問題定義から各ケースの入力を生成し、学習者のコードへ与えてresultを取得する。学習者の提供コードのコピーや初期化を正式入力として信用しない。採点用期待値は学習者プロセスへ送らず、クライアントからexecution契約を指定することも許さない。

表示例と異なる値・shapeの採点ケースを維持し、表示結果の直接代入が落ちることを検証する。行平均ではmean、sumで割る方法、Pythonで各行を計算する方法も受け入れる。入力再定義と、問題で禁じた入力変更は区別する。156問×2バリエーションで表示値の直接代入を不正解として検出し、in-placeの別解と集計用カウンターも検証した。

公開・非公開を別Sandboxで実行するため、正式Submitは非公開ケースのある問題で2回の起動になる。非公開側のstdout、値、個別エラー詳細は学習者へ返さない。キャンセルが2回目の起動と競合する場合も停止し、正解として保存しない。

予測問題20問は「このコードのこの入力の結果」を回答するので、固定の1観察へ変更した。配列の値をリストで回答するときは、表示された配列のdtypeをアダプターが補い、不要な配列生成コードを入力させない。値の直接回答はこの形式では正しい解答方法であり、汎用処理のハードコードとは区別する。

## 5. 履歴・進捗・連続演習

180問ともcontent_versionを1つ進めた。旧版は`content/versions/v1-seed*.json`と、Phase 1完了時の`v2-seed*.json`を保持する。新しい問題は15問が@3、165問が@2。今回の詳細改稿15問と、以前@2だった15問は完全には同じ集合ではない。

過去のitem、Draft、Attemptの版・seed・コードを書き換えるDB移行は行わない。履歴は当時の問題定義を参照し、進捗は既存familyのまま集計する。新しいworkspace/executionは追加フィールドであり、旧版には従来のUIと関数ハーネスを使う。旧セッションを実際に開いて実行・保存するE2Eも残した。

Guided2問、Independent完了、目標20問、キュー末尾を終了条件にしない。21問の実解答でG→P→I→次の概念と、同じセッションの継続・履歴21件を確認する。終了は学習者の操作だけで行う。

## 8. 未解決事項と次の順序

| 優先 | 残る課題 | 理由・次にすること |
|---|---|---|
| High | Modalの実接続と2回起動時の待ち時間 | 認証情報を使う本番相当テストは未実施。設定後にRun/Submit・キャンセル・正式認定を確認する |
| High | 残る165問の詳細な教材改稿 | 具体入力の仕様は統一したが、第1・第2ヒントや説明文の専門用語は人手の品質確認が必要 |
| Medium | 誤答に対応する診断 | 現状は問題ごとの確認事項と実値比較。ASTや実行情報で原因を確実に識別した診断までは導入していない |
| Medium | APIの厳密な意味の検証 | 呼び出しや出力だけではmergeのvalidate、stratify、クラス構造の正しい利用を完全には証明しない。例外を含むケース設計と構造検証を次の版で行う |
| Medium | 初学者・実機での操作確認 | 自動テストは画面と動作の確認であり、認知負荷の実証ではない |
| Low | 一部の長い入力や履歴コードの見せ方 | 大きな表の見通し、予測の内部互換コードの履歴表示を次に評価する |

定数出力しか観察できない問題はAPI呼び出しと直接代入の検査を併用する。任意Pythonコードの意味を完全に解析して、巧妙な偽装をすべて排除する仕組みではない。

- Pythonの基本だけを知る人に、問題を開いて「何を・どの入力で・どこへ書くか」を言い換えてもらう。最初に選んだ編集箇所と立ち止まった点を記録する。

- PD02で欠損値と学習時の平均、SK02でtrain/testを分ける理由が伝わるか確認する。
- PT02の転置、PT05のforward、PT07の勾配を消す場所が、入力とコードから分かるか確かめる。
- スマートフォンの実キーボード・日本語IME・縦横回転で、データを確認して回答できるか試す。デスクトップのキーボード操作と読み上げも確認する。

## 10. 開発環境への反映

既に起動していた通常の開発サーバーと学習DBは操作していない。新版を通常環境で開くときは、コンパイル済み問題を読み込むAPIを再起動する。旧セッションは旧版を保持するので、新しい問題形式を確認する場合は新しい演習を開始する。検証用8001/5174はテスト終了時に停止する。
